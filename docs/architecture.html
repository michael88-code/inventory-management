Architecture overview

Factory Inventory Management System

A demo dashboard for a factory's inventory, orders, demand, spending and reports. It has a Vue 3 single-page app in the browser and a Python FastAPI service behind it. All data comes from JSON files that are loaded into memory, so there is no database.

System architecture

Two processes run on your machine. The browser loads the app from Vite on port 3000, and the app then calls the API on port 8001 for data.

Tech stack

A small, modern stack with no database, no build-time CSS framework and no chart library. Charts are hand-drawn SVG.

Data flow: changing a filter

This is what happens when a user picks "Tokyo" in the warehouse filter on the Dashboard.

  1. User changes a filter

    FilterBar.vue writes to selectedLocation, a shared ref in useFilters.js. Every view sees the same four filter values.

  2. The view reacts and refetches

    Dashboard.vue watches the filters, calls getCurrentFilters(), and fires four requests in parallel: summary, orders, inventory and backlog.

  3. api.js builds the request

    Filters set to "all" are dropped. The rest become query params, for example GET /api/orders?warehouse=Tokyo&month=Q1-2025.

  4. FastAPI filters in memory

    apply_filters() narrows by warehouse, category and status. filter_by_month() handles a single month (2025-03) or a quarter (Q1-2025).

  5. Pydantic validates the response

    Endpoints declare a response_model, so the output is checked against the model and returned as JSON.

  6. Vue recomputes and re-renders

    Raw responses go into refs (allOrders, inventoryItems). Computed properties derive the KPIs, charts and tables, and the page updates.

Things worth knowing

These gaps showed up while reading the code. They're useful context before you build new features.

  • The frontend calls endpoints that don't exist.api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders, but main.py doesn't implement them, so those requests return 404. The task list only shows the built-in mock tasks from useAuth.js, and adding, deleting or completing a task fails quietly with only a console error.
  • No data is saved. Everything lives in memory. Restarting the server reloads the JSON files, and purchase_orders.json is empty.
  • The Backlog page has no route. views/Backlog.vue exists but isn't registered in main.js. Backlog data appears only on the Dashboard.
  • Reports skips the shared API client. Reports.vue calls axios directly with a hardcoded URL instead of going through api.js.
  • Some numbers ignore the filters. The backlog count on the dashboard summary is always the full total, and inventory has no time dimension, so the month filter doesn't apply to it.
  • The setup is for development only. The API URL is hardcoded to localhost:8001, CORS allows every origin, and there's no authentication.
